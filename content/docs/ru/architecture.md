Интерактивная схема на странице [Начало работы](/docs) следует теме сайта. Все три клиента обращаются к одному API; запросы к моделям уходят через шлюз.

```
easytv-web      ──┐
easytv-manage   ──┼──▶  easytv-api (Gin)  ── MySQL / Redis
easytv-partner  ──┘           │            ── object storage (local / OSS / Qiniu)
                              │            ── ffmpeg
                              ▼
                    OpenAI-compatible gateway
                              ▼
                    Kling · Jimeng · Seedance · Sora · GPT · …
```

## Авторизация

- Студия и кабинет партнёра: `Authorization: Bearer <token>` плюс `EasyTV-User: <user id>`
- Админ-панель вызывает `/admin/*`, нужна `role ≥ 10`
- Командное пространство использует `EasyTV-Team: <team_id>`; по умолчанию — личное пространство
- CORS возвращает origin запроса, поэтому три фронтенда могут находиться на разных хостах

## Конфигурация во время работы

Переменные окружения читаются один раз при запуске процесса. Название сайта, платежи, адрес шлюза, правила приглашений и подобное хранятся в таблице `setting` бэкенда. Изменения в админ-панели применяются сразу; перезапускать API не нужно.

Хранилище — одно из трёх: локальный каталог `upload/`, Aliyun OSS или Qiniu. Для генерации видео по изображению шлюз должен скачать исходник: OSS / Qiniu уже отдают публичные URL; для локального хранилища нужен `UPLOAD_BASE_URL` (или настройка `UploadBaseUrl`), чтобы шлюз мог получить файл.

API на нескольких узлах использует `WORKER_TAG`: каждый процесс обрабатывает только задания с тем же тегом.
