title: ワンプロンプト制作
description: ひと言を入力するだけで、企画書の作成、レイヤーごとの生成、字幕付き完成映像の合成までを自動で行います。
---

パスは `/create` です。ウィザードの流れは、入力 → 企画書 → レイヤーごとの生成 → 合成 → 完了です。契約は `API.md` の 8.2 節にあります。

![ワンプロンプト制作](/images/docs/create.png)

匿名でも最初のステップは見られます。「企画書を生成」を押した時点でログインが必要になります。状態は企画書の id をキーに sessionStorage へ保存され、再読み込みや `?screenplay=` で続きから再開できます。

## 流れ

### 1. 入力

ひと言（上限は約 8000 文字）、長さ 15 / 30 / 60 秒、任意でスタイル。`POST /user/screenplay` はテキストモデルを同期的に呼び出して企画書を書き、テキストの単価で 1 回分のクレジットを引き落とします。

既定のテキストモデルの優先順位：今回選択したもの → 前回記憶したもの → 管理コンソールの **グロース** にある `ComposePlanModel` → 価格表の最初のテキストモデル。

### 2. 企画書

構造はおおよそ次のとおりです：

```json
{
  "title": "",
  "style": "cinematic, cool grade",
  "aspect": "16:9",
  "characters": [{ "key": "c1", "name": "", "look": "wardrobe" }],
  "scenes": [{ "key": "s1", "name": "", "look": "set" }],
  "shots": [{ "no": 1, "scene": "s1", "characters": ["c1"], "prompt": "frame", "motion": "camera", "line": "dialogue", "seconds": 5 }]
}
```

検証：カット ≤ 12、キャラクター ≤ 4、シーン ≤ 4。保存は `PUT /user/screenplay/:id` で行います。

`POST /user/screenplay/:id/estimate` は、選択した画像 / 動画 / 音声モデルに基づいて、キャンバス作成後の各レイヤーのクレジットを見積もります。

### 3. キャンバスの作成とレイヤーごとの生成

`POST /user/screenplay/:id/build` は新しいキャンバスを 1 枚作成します（プロジェクトがなければ併せて作成します）：

- テキストノード：企画書の要約
- キャラクターごとに画像 1 枚（`sp.layer=character`）
- カットごと：カット画像 → 動画 → セリフがあればナレーション

そのあと、キャンバス上でレイヤーごとに実行するか、ウィザードにまとめて送信させます。画像、動画、音声の既定モデルは、それぞれ setting の `ComposeImageModel` / `ComposeVideoModel` / `ComposeAudioModel` から読み込まれます（管理コンソールの **システム / グロース → 完成映像と分配**）。ゲートウェイ側である経路が使えなくなった場合は、この 3 つのキーを変えるだけで済み、コードの変更は不要です。

### 4. 合成

`POST /user/canvas/:id/compose` は成功済みの動画ノードを取得し（x または `clip_order` の順）、ffmpeg で 1280×720 / 30fps に統一し、SRT を焼き込み、BGM をミックスします（-14 dB）。無料ユーザーには右下に `EasyTV.ai` の透かしが入ります（`ComposeWatermarkEnabled` が有効で、かつ非会員の場合）。

合成では **クレジットを消費しません**。1 ユーザーにつきキュー待ち / 合成中が 3 件以上あると先に拒否され、全体のキューが 20 件以上の場合も拒否されます。10 分を超えると失敗として扱われます。`GET /user/compose/:id` をポーリングしてください。

完成映像は `source=compose` としてアセットライブラリに入り、コミュニティの `/watch/:id` に公開できます。

## よくある失敗

- 企画書の解析に失敗：API がテキストモデルを自動で 1 回リトライします
- 画像から動画で 502：ゲートウェイのチャネルによっては、テキストから動画は正常でも画像からは必ず失敗するものがあります。`ComposeVideoModel` を動作確認済みのモデルに変更してください
- ゲートウェイの 429 / 503：バックエンドは最大でさらに 2 回リトライします（`Retry-After` に従います）。それでも失敗すると「模型当前排队较多」を返します
