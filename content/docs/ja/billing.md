制作で消費されるのは **クレジット** だけです。旧仕様の `quota` は出金などの旧機能のためだけに残っており、生成には使われません。契約は `API.md` の第 6 章にあります。

![管理コンソールのダッシュボードに表示されるクレジットと売上](/images/docs/admin.svg)

## クレジットの仕組み

- 付与は「ロット」単位です：付与元 + 数量 + 有効期限。消費は **有効期限が最も近いものから** 行われます
- 残高 = 期限内のロットの残量の合計
- タスクの作成時に、モデルのパラメータに応じて **事前引き落とし**（`freeze` の取引）を行います。成功時は `settle`（金額 0。見積もりがそのまま精算額）、失敗 / キャンセル時は有効期間 365 日の `refund` ロットとして返金されます
- **価格が設定されていないモデルではタスクを作成できません**
- サーバー側で価格を再計算するので、フロントエンドに表示される見積もりは参考値です。注文レスポンスの `price` が実際の支払額です

モデルの単価は `model_price` にあります：

| フィールド | 意味 |
| --- | --- |
| `type` | `text` / `image` / `video` / `audio` |
| `unit` | `second`（動画は秒単位）/ `image`（枚単位）/ `call`（テキスト、音声は回数単位） |
| `points_per_unit` | 標準価格 |
| `member_points_per_unit` | 会員価格。0 は標準価格と同じ |

見積もり：動画は `duration × count × unit`、画像 / テキスト / 音声は `count × unit`。タスク作成時の `count` は 1 のみで、一括生成はフロントエンドが複数のタスクに分割します。

価格取り込み時の推奨クレジット：ゲートウェイの米ドル原価 × 為替レート（既定 7.3）× 利益率係数（既定 3）× 1 元あたりのクレジット（既定 20）。従量課金のモデルは、想定 token 使用量をもとに回数 / 枚 / 秒に換算されます。運営担当はゲートウェイ設定でこれらの係数を変更できます。

## 会員とクレジットパック

会員プラン（`starter` / `creator` / `pro` / `flagship`）は毎月クレジットを付与し、有効期間中の生成には会員価格が適用されます。加入するとすぐに初月分が付与され（有効期間 31 日）、以降はバックグラウンドジョブが付与日に合わせて補充します。

クレジットパックは日数単位で有効です（30 / 90 / 365 / 730）。会員がクレジットパックを購入する場合は `member_price` が適用されます。

年払い / 四半期払いの割引、チームシートの割引は setting の `BillingPromo` JSON に書かれており、期限を過ぎると倍率はすべて 1 に戻ります。

無料アカウントには、同時実行数とクラウドストレージの上限もあります（`FREE_CONCURRENT` / `FREE_STORAGE_GB`。会員プランで上書きされます）。

## 注文

スタジオの `/pricing`：`POST /user/order`。`payment_method` は次のいずれかです

- `wechat_native`：`code_url` を返し、フロントエンドが QR コードを描画します
- `alipay_f2f`：対面決済の QR コード
- `alipay_pc`：決済ページ `payment_url` にリダイレクトします

決済チャネルが無効な場合、注文は `pending` のままで、`pay` は null になります。`order_no` は決済の取引番号も兼ねます。WeChat Pay の `/wechat/webhook`、Alipay の `/alipay/webhook` へのコールバック後に履行（会員またはクレジットの付与）され、処理は冪等です。

## 管理コンソールで設定するもの

1. **システム → サイト**：`ServerAddress` に API の公開ルートアドレスを入力します（末尾のスラッシュは不要）。コールバック URL の組み立てに使われます
2. **システム → 決済**：WeChat Pay APIv3 Native、Alipay 証明書モード（対面決済 / PC サイト決済は個別に設定可能）
3. **会員プラン / クレジットパック / モデル価格** の 3 ページで商品を管理します
4. ローカルで決済をつなぎたくない場合：ユーザーページでテストアカウントに手動でクレジットを追加します

請求書、返金、手動での支払い済み処理は、スーパー管理者（`role ≥ 100`）のみ行えます。
