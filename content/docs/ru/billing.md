Создание расходует только **кредиты**. Устаревшее поле `quota` используется для вывода средств и подобного; в генерации оно не участвует. Контракт: глава 6 API.md.

## Как устроены кредиты

- Каждое начисление — это **партия**: источник + количество + срок действия. Первыми расходуются партии с самым ранним сроком
- Баланс = остаток по неистёкшим партиям
- Создание задачи **предварительно списывает** кредиты (`freeze`); при успехе выполняется `settle` (сумма 0 — оценка окончательна); при сбое / отмене возвращается партия `refund` на 365 дней
- **Модели без цены не могут создавать задачи**
- Сервер пересчитывает цену. Число на клиенте — ориентир; платите вы то, что указано в `price` в ответе на заказ

Цены за единицу хранятся в `model_price`:

| Поле | Значение |
| --- | --- |
| `type` | `text` / `image` / `video` / `audio` |
| `unit` | `second` (видео) / `image` / `call` (текст, речь) |
| `points_per_unit` | обычная цена |
| `member_points_per_unit` | цена для подписчиков; 0 — такая же, как обычная |

Оценка: видео — `duration × count × unit`; изображение / текст / речь — `count × unit`. При создании `count` должен быть равен 1; пакеты разбивает клиент.

Рекомендуемые кредиты при импорте: стоимость на шлюзе в USD × курс (по умолчанию 7.3) × наценка (по умолчанию 3) × кредитов за юань (по умолчанию 20). Модели с оплатой по токенам приводятся к вызову / изображению / секунде исходя из предполагаемого расхода токенов. Операторы могут изменить эти коэффициенты в настройках шлюза.

## Подписка и пакеты

Тарифы (`starter` / `creator` / `pro` / `flagship`) дают ежемесячные кредиты и цены для подписчиков, пока подписка активна. При оформлении тарифа кредиты за первый месяц начисляются сразу (партия на 31 день); далее задание по расписанию пополняет баланс в день начисления.

Пакеты кредитов действуют 30 / 90 / 365 / 730 дней. Подписчики покупают пакеты по `member_price`.

Скидки за год / квартал и скидки на командные места хранятся в настройке `BillingPromo`. После `ends_at` все коэффициенты равны 1.

У бесплатных аккаунтов также есть ограничения на параллельные задачи и хранилище (`FREE_CONCURRENT` / `FREE_STORAGE_GB`; тарифы их переопределяют).

## Оплата

Страница студии `/pricing` вызывает `POST /user/order` с одним из способов:

- `wechat_native` — `code_url` для QR-кода
- `alipay_f2f` — QR-код для оплаты «лицом к лицу»
- `alipay_pc` — `payment_url` на кассу Alipay

Если канал отключён, заказ остаётся в статусе `pending`, а `pay` равен null. `order_no` служит и номером платёжной операции. WeChat `/wechat/webhook` и Alipay `/alipay/webhook` исполняют заказ (выдают тариф или кредиты) идемпотентно.

## Чек-лист для админ-панели

1. **Система → Сайт**: `ServerAddress` — публичный корневой адрес API (без завершающего слеша) для обратных вызовов
2. **Система → Платежи**: WeChat APIv3 Native, Alipay в режиме сертификатов (F2F / PC можно настроить отдельно)
3. Поддерживайте **тарифы / пакеты / цены на модели**
4. Для локальных тестов начисляйте кредиты на странице «Пользователи», не подключая платежи

Для счетов, возвратов и отметки «оплачено» нужен суперадминистратор (`role ≥ 100`).
