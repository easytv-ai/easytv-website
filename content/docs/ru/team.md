## Вход

У студии и кабинета партнёра единая система учётных записей.

| Способ | API | Примечания |
| --- | --- | --- |
| E-mail + пароль | `POST /user/login` | |
| SMS-код | `GET /sms/verification` + `POST /user/sms_login` | Автоматически регистрирует, если пользователя нет |
| WeChat Open Platform | OAuth | Задайте хост обратного вызова в админ-панели; в разработке одноразовые коды можно выводить в лог API |

Ответ содержит `access_token`. После этого каждый авторизованный запрос отправляет:

```
Authorization: Bearer <access_token>
EasyTV-User: <user_id>
```

Админ-панель использует `/admin/*`, нужна `role ≥ 10`. Для системных настроек, возвратов и корректировок кредитов нужен суперадминистратор с `role ≥ 100` (учётная запись `admin`, созданная при первом запуске).

Администраторы могут выпустить одноразовый ticket для входа в студию или кабинет партнёра (вход от имени пользователя для поддержки).

## Командное пространство

В шапке студии: **личное** / **командное**. Пользователь состоит не более чем в одной команде. Заголовок `EasyTV-Team: <team_id>` (отсутствует или 0 — личное пространство).

Правила:

1. Личное пространство всегда расходует ваш собственный кошелёк, даже если вы состоите в команде
2. Командное пространство расходует **пул кредитов владельца**; при истёкшем командном тарифе запрос отклоняется (`team_expired`)
3. Существующие проекты остаются личными; автор может перенести их в команду или обратно
4. Роли `admin` / `editor` / `viewer`. Наблюдатели (viewer) не могут генерировать за счёт кредитов команды
5. Если вас исключили, API возвращает `team_forbidden`; клиент должен убрать заголовок и переключиться обратно

Подписка бывает в авторской редакции на одно место и в командной редакции (2–10 мест, скидка в `BillingPromo`). Параллельные задачи и хранилище зависят от тарифа.
